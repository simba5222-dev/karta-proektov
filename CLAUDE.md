# Карта проектов (karta)

Живая карта трёх направлений: механизация, отдел продаж, бот MAX.
Показывает состояние, алгоритмы работы каждого проекта и журнал того, что мы делали.

Отдаётся nginx по адресу `http://72.56.25.105/karta/`, закрыта basic-авторизацией
(`/etc/nginx/.htpasswd-karta`, пользователь `karta`), индексация запрещена заголовком.

## Как устроено

| Файл | Что это |
|---|---|
| `data.json` | **всё содержание**: блокеры, проекты, алгоритмы, задачи, журнал |
| `style.css` | вёрстка, светлая и тёмная темы |
| `build.py` | сборка `index.html` из первых двух. Только stdlib, зависимостей нет |
| `deploy.sh` | собрать и скопировать в `/var/www/karta/` |
| `index.html` | результат сборки, в git не хранится |

Правится **только `data.json`**, потом `./deploy.sh`. Руками `index.html` не трогать —
следующая сборка его перезапишет.

Тексты в JSON — это готовый HTML внутри абзаца: можно писать `<code>`, `<b>`, `<em>`.
Экранирования нет намеренно, файл пишем мы сами.

## Главное правило

**Эта карта — журнал работы, а не снимок состояния.** Владелец просил, чтобы на ней
отражалось всё: обсуждения, планы, выполненные работы, принятые решения.

В конце каждого сеанса дописывать в `journal` записи за сегодняшнюю дату. Типы:

- `решение` — что решили и **обязательно `why`**, иначе через месяц непонятно, почему так
- `сделано` — что реально сделано
- `выяснено` — что обнаружили: блокер, особенность среды, ложная гипотеза
- `открыто` — вопрос, который завис и ждёт ответа

Поле `who` заполняется, когда решение принял владелец, а не агент.
Новые дни добавляются в любое место массива — сортировка по дате делается при сборке.

## Запуск

`deploy.sh` вызывает `sudo cp`, поэтому запускать под `agent` (у него sudo без пароля).
Под `claude` sudo спросит пароль.

Сборка без выкладки — `python3 build.py`, файл появится рядом.

## Чего не делать

- **Не печатать на странице секреты.** Она отдаётся по http, без шифрования: ни паролей,
  ни токенов, ни реквизитов. Про дефолтный пароль механика написано, что он дефолтный,
  но само значение не приводится — так и оставить
- Не хранить `index.html` в git — он собирается
- Не заводить зависимости: `build.py` должен работать системным python3 без venv
